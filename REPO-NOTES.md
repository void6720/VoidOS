# VoidOS — repository notes

This repo holds the **source** of the VoidOS project. Build outputs (disk
images, the assembled rootfs package tree, screenshots) are not tracked —
they are regenerated by the build scripts.

## Layout

- `boot/`, `kernel/` — the original from-scratch VoidOS kernel (NASM
  bootloader + freestanding C kernel: VBE framebuffer GUI, PS/2 input,
  terminal shell). Boots under QEMU. See `README.md` and `Makefile`.
- `distro/` — **VoidOS Linux (XFCE edition)**, the active track:
  Alpine-based x86_64 distro with a musl/BusyBox userland, OpenRC init,
  LightDM + XFCE desktop, and a custom boot splash.
  - `distro/run-linux.sh` — QEMU launcher (direct kernel boot, user NAT
    with an SSH host-forward on 127.0.0.1:2222, Intel HDA audio,
    qemu-xhci USB).
  - `distro/build/make-image.sh` — builds the 3 GiB ext4 disk image from
    `distro/rootfs/` (must run under fakeroot). The rootfs itself is
    assembled with `apk.static` from Alpine packages plus the
    hand-authored files mirrored under `distro/build/overlay/` and the
    paths below.
  - `distro/build/splash/make_splash.py` — generates the boot splash
    image (drawn early in boot by an OpenRC service using fbsplash).
  - `distro/build/audit_rootfs.py` — structural audit of the rootfs
    (layout, symlink health, library resolution).
  - `distro/vdrive.py`, `distro/vnc.py` — guest automation helpers
    (QEMU monitor / VNC input) used to drive and screenshot the VM.
  - `distro/rootfs/usr/local/bin/vpm` — **vpm**, VoidOS's package
    manager (POSIX-sh frontend over apk).
  - `distro/rootfs/etc/init.d/voidos-splash` — boot splash service.
  - `distro/rootfs/etc/network/interfaces` — guest networking (DHCP on
    eth0; required for the SSH forward to reach sshd).

## ChromiumOS-derived components

- **crosh** (`distro/build/crosh/crosh.classic`, installed as
  `/bin/crosh`): the classic interactive ChromiumOS developer shell from
  the archived `chromiumos/platform/crosh` tree, BSD-licensed, with its
  shebang adapted to `#!/bin/bash` (BusyBox ash lacks `read -e`).
- **minijail** (installed as `/bin/minijail0`, with `libminijail.so` /
  `libminijailpreload.so` in `/lib`): Google's sandboxing engine,
  compiled natively inside VoidOS from the upstream `google/minijail`
  sources against musl + libcap. The compiled binaries are build
  outputs and are not tracked here.
- metrics_client / power_manager tools were evaluated and **not**
  integrated: their BUILD.gn dependency chains pull in the full
  ChromiumOS C++ stack (libmetrics → structured metrics →
  libbrillo/libchrome), which does not fit a lightweight standalone
  musl target.

## Not in this repo

- `distro/build/voidos-linux.img*` — built disk images (3 GiB each).
- The full `distro/rootfs/` package tree (Alpine binaries, ~1.6 GiB) —
  only the hand-authored files listed above are mirrored.
- Screenshots and boot videos under `distro/shots/` and `distro/*.png`.
